## 발견한 문제점·주의

1. DB하이텍의 조회 결과 접수번호(20260601001661)는 `[기재정정]사업보고서 (2025.12)`다(list.json으로 확인, 원본 사업보고서는 20260316001250). API는 최신 정정본 기준으로 응답한 것으로 보이며, **확정 정책: 최신 정정본 기준**으로 사용하고, 원본 접수번호는 이력으로 보관하며, 출처에 [기재정정]을 표기한다. 계정명은 account_id 기준으로 정규화한다. 삼성전자·SK하이닉스는 정정 없이 원본(2026-03)이다.
2. 재무 데이터에는 접수번호 외 원문 링크가 없으므로 DART 뷰어 링크는 `https://dart.fss.or.kr/dsaf001/main.do?rcpNo={rcept_no}` 형식으로 만든다(링크 형식은 구현 시 열어 확인 필요).
3. 분기·누적 기간 검증(2026-11-06 실응답 확인): 2026 반기보고서(reprt_code 11012)는 계정마다 `thstrm_amount`(해당 3개월)와 `thstrm_add_amount`(누적 6개월)를 함께 준다. 삼성전자 연결 매출 확인: 1분기 133.87조 + 2분기(3개월) 171.50조 = 305.37조 = 반기 누적과 일치. 1분기 보고서는 두 값이 같다. SK하이닉스·DB하이텍도 동일 구조(DB하이텍 반기 누적 매출 774.05십억원대, 3개월 414.45십억원대 확인). 규칙: 비율은 분자·분모를 같은 기간 필드(둘 다 3개월 또는 둘 다 누적)로 계산하고, 기간(3개월/누적)을 Claim Ledger에 기록하며, 연간 값과 분기 값을 섞으면 "기간 불일치"로 플래그한다. 3분기 보고서(reprt_code 11014)는 2026-11-06 기준 제출 전이라 미확인.
4. 3사 모두 적합하며 대체 후보는 필요하지 않다. 매출 규모 차이가 크므로(삼성전자는 DB하이텍의 약 240배) 비율 지표 비교는 무방하나 절대금액 비교는 단위 표기를 맞춰야 한다.
